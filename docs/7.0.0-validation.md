# FreePDF 7.0.0 development validation

This is `7.0.0-dev.1`, not a stable or published package. The MIT Preview 1 source
is imported with ancestry; independent changes are reviewed separately below.

## Independent corrections

| Requirement | Implementation | Evidence |
| --- | --- | --- |
| Tolerate non-name dictionary keys | Coerce string/integer keys to names; reject other types | `ReaderToleranceTests`: read/save/reopen and rejection fixtures |
| Legacy name bytes | Strict UTF-8 first, then current-culture ANSI with CP1252 fallback | UTF-8, literal replacement character, CP1252 and Shift-JIS fixtures; no claim that ambiguous bytes identify their original encoding |
| PNG memory failure | Exclude `OutOfMemoryException` from both importer fallback catches | Synthetic impossible array length; ordinary invalid image still uses fallback |
| Signature field collisions | Traverse root/nested fields with cycle guard; select first unused SignatureN | Existing fields and two real insertion calls; dummy signer, no cryptographic validity claim |
| Font cache races/staleness | Atomically publish immutable weak-reference pair and font properties | 40,000 parallel conversions plus same-font mutation |
| Core StartFigure (#396) | Track a pending new subpath and preserve it across cloning | Two synthetic path-operator tests and visual fixture |
| Fully merged table (#358) | Find minimum vertical extent among visible cells of a starting row | 2×2/3×3 merge regressions; visual fixture plus normal multi-page tables |
| Truncated hexadecimal strings | Detect EOF in both reader scanners; content whitespace/odd-nibble support | Bounded malformed-content cases and valid odd/whitespace cases |
| Earlier fixes | Carry gradient state reset, inline-image EOF, zlib footer/framing | Earlier 6.2.5 regressions retained |

Source inputs: permitted MIT snapshots, public issue facts and changelog
requirements, original fixtures, RFC 1950. Later AGPL PDFsharp implementations
were not read or imported. `PROVENANCE.md` records details and asset licences.

## Observed local checks (2026-10-30)

- 77 regression cases passed on Linux/.NET 10 after the cryptography dependency patch.
- Core PDF/MigraDoc rendering built for .NET Standard 2.0.
- Both lab generators built for .NET 10 and .NET Framework 4.6.2. Linux compilation
  of Framework targets does not prove Windows execution; CI runs those consumers.
- Lab pixel/PPM/PNG self-checks passed.
- NuGet vulnerability audit reported no vulnerable packages in the FreePDF
  generator graph, including transitive dependencies, against the current feed.
- Twelve real reference/candidate cases ran with MuPDF 1.25.1, 144 DPI and fixed
  DejaVu Sans. Nine cases matched with **zero pixel delta**, including two-page
  paragraphs/tables, attachment bytes, and checkbox field count/appearance.
- Three cases remain visible for review: gradient-to-solid fill (7.9365% changed),
  StartFigure (3.0627% changed), and full-table merge (reference generation fails,
  candidate succeeds). Original regressions support the intended corrections;
  upstream output is not assumed correct when it demonstrates a known defect.
- Browser QA checked case selection, loaded images, overlay opacity, difference
  selection and absence of horizontal overflow at desktop and 390px widths.

The `Core build` workflow runs Linux core/RTF builds for .NET 8/10/Standard,
regressions on Linux/Windows .NET 8/10 and Windows Framework 4.7.2, and GDI/WPF
builds for modern Windows and Framework 4.6.2. `Comparison lab` adds real fixture
execution/pixel comparisons on Linux .NET 10 and Windows .NET 10/Framework 4.6.2,
with reports/PDFs/PNGs uploaded as artifacts. Check the actual run conclusion;
workflow configuration is not evidence of a pass.

## Remaining stable-release gates

Public API/migration review; distinct FreePDF package IDs/internal dependencies;
full dependency/license audit; independent PDF/A and signature validation;
additional malformed-input and broad real-world synthetic fixtures; supported
runtime policy including the inherited .NET 9 target. The typed v7 form model
contains placeholder classes; the low-level checkbox fixture does not certify
general form filling/flattening. No PDF/UA or complex-script shaping claim.

The Tomahawk25 installation is prepared separately. Local preview and CI are not
proof of a permanent Windows service/task, scheduled runs, host restart recovery,
or LAN firewall behavior. Record those checks after an approved installation.
