# 6.2.5 first-batch validation

Recorded 2026-10-30. These are synthetic regression checks for three changes,
not certification of the complete PDFsharp/MigraDoc feature set.

## Regression evidence

Before changing the graphics state or scanner, the original 6.2.4 implementation
failed 15 of 27 new cases: 12 transparency cases and three truncated headers.
The same suite passed after the fixes.

The unchanged Flate encoder then failed all 16 initial checksum/round-trip cases.
After adding zlib framing, the combined suite passed. Three further maximum-byte
vectors exercise checksum accumulation at and beyond its reduction boundary.
The final local .NET 10 run passed **46 tests, zero failures or skips**.

```sh
dotnet test src/tests/FreePDF.RegressionTests/FreePDF.RegressionTests.csproj --configuration Release --framework net10.0
```

The suite uses no external fonts, asset downloads, or customer documents. The
seven larger platform-zlib comparisons require modern .NET; .NET Framework runs
the other 39 cases. CI defines Linux/Windows .NET 8/10 runs, a Windows .NET
Framework 4.6.2 run, core/MigraDoc builds, and Windows GDI/WPF builds. Check the
pull request's actual job results before treating that matrix as passed.

## Independent generated-PDF checks

A two-page synthetic PDF exercises RGB and CMYK paths with first transparent
fill/stroke, opaque paint, and solid black after a gradient. Both page-content
streams passed Python's zlib decompressor with `eof == true` and no trailing
unused data. This checks complete framing in a saved PDF, not only filter calls.

MuPDF and Poppler both rendered both pages at 72 dpi. Pixel assertions confirmed
white at the transparent shapes, dark opaque shapes, and a colored gradient;
the four-image contact sheet was also inspected. CMYK color appearance differs
between the renderers, as expected from their color-management paths. MuPDF
reported that ICC support is unavailable in the installed build; these results
do not establish colorimetric accuracy or PDF/A conformance.

Internal evidence is retained at `/nas/qa/freepdf/2026-10-30-6.2.5/`:
synthetic generator and PDF, four renders, contact sheet, stream/pixel results,
and before/after TRX files. All fixtures were created for this work.

## Limits before a stable release

- This batch preserves the existing public source APIs. A complete public API
  and package-compatibility comparison remains a release gate.
- Windows variant compilation is separate from exercising GDI/WPF rendering.
- Existing MigraDoc layout, font, form, signature, encryption, and PDF/A paths
  are not comprehensively validated by these tests.
- Distinct FreePDF package IDs and dependency mapping must be completed before
  publishing. No package or stable release is produced by this change.

See [upstream feature tracking](upstream-feature-tracking.md) for the remaining
feature and fix candidates.
