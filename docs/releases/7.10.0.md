# FreePDF 7.10.0

FreePDF 7.10.0 signs PDFs the way EU and eIDAS contexts expect (PAdES baseline
signatures, ETSI EN 319 142-1), keeps them verifiable after the signer's
certificate expires (validation data and document time-stamps, B-LT and B-LTA),
and checks the signatures of a file: intact or not, who signed and when, trust,
revocation, and later changes.

## New

### PAdES signatures

- **PAdES B-B and B-T.** `PdfSharpDefaultSigner` with
  `Format = PdfSignatureFormat.Pades` writes `ETSI.CAdES.detached` signatures:
  the signing-certificate-v2 attribute binds the signer's certificate, there is
  no signing-time attribute (the claimed time is the dictionary's /M), and SHA-1
  is refused. With a time-stamp authority the signature gets a signature
  time-stamp and is B-T. Below PDF 2.0 the catalog declares the ESIC extension,
  keeping the declarations it has. The default format is unchanged
  (`adbe.pkcs7.detached`).
- **Injectable time-stamp client.** `PdfSharpDefaultSigner.TimeStampClient`
  sends the RFC 3161 request through a function of your own (authentication, a
  test authority); `TimeStampReserve` is the room kept for the token.
- **Your own signer.** `IDigitalSignerFormat` lets a custom `IDigitalSigner`
  report its format; a field's required /SubFilter seed value is checked against
  it.

### Long-term signatures

- **Validation data.** `PdfDocumentSecurityStore.AddValidationDataAsync`
  collects the chains of a document's signatures and time-stamps and, for each
  certificate below a root, an OCSP response or else the CRLs, and writes them
  into the document security store (DSS) in an update in Append mode. The
  addresses come from the certificates, so the default client reaches only
  public addresses (checked again at connection and on every redirect), uses no
  proxy, limits answers to 32 MiB and 30 seconds, and takes a cancellation
  token; pass your own `HttpClient` for a proxy or an internal CA.
  `PdfDocumentSecurityStore.Add` writes data you fetched yourself.
- **Document time-stamps.** `PdfTimeStampSigner` adds a document time-stamp
  (`ETSI.RFC3161`) over the document and its validation data: B-LTA.
- **Under a "no changes" certification.** A document certified with P=1 now
  takes validation data and invisible document time-stamps, as ISO 32000-2
  permits, and nothing else; such an update leaves the document information as
  it was.

### Verification

- **`PdfSignatureVerifier`.** For each signature and document time-stamp:
  whether the covered bytes are intact (and belong to that signature dictionary
  and field in the signed revision), the signer and chain, trust (the roots you
  give, or the system's), the claimed and the time-stamped signing time,
  revocation from the DSS or online, the first later change its certification
  or field locks forbid, a later change that goes beyond form filling, signing
  and validation data after an approval signature, and the PAdES level from B-B
  to B-LTA. A certificate that expired since counts if it was valid at a trusted
  signature time-stamp. Each result is Valid, Invalid or Indeterminate, with
  reasons. It is a technical check, not a statement about legal effect.

## Changed

- **Signature time-stamps ask the authority once.** The authority was asked
  twice per signature, once only to size the placeholder; the placeholder now
  reserves `TimeStampReserve` bytes (16384), so a time-stamped signature takes
  about 30 KB more. A larger token fails the save with a message naming the
  setting.
- **Signed saves to a path are atomic.** A signed document saved to a path goes
  through memory and a temporary file that replaces the target, as Append-mode
  saves do. A failed signature (a refused or unreachable time-stamp authority)
  left a truncated file before.
- `PdfSharpDefaultSigner` refuses a null certificate with
  `ArgumentNullException` and keeps 8 bytes to spare instead of 4 (ECDSA).
- The core assembly references System.Security.Cryptography.Pkcs, which every
  FreePDF package already depended on.
- .NET 11: CI installs the published packages in .NET 11 applications and runs
  the regression tests on the .NET 11 runtime.
- The 7.9.0 release notes named pyHanko 0.6.0; that is its command-line package.
  The library was 0.38.1.

## Validation

All 7.9.0 release gates apply, plus:

- 97 new regression tests, 1059 in all, among them tests for each attack the
  reviews found that can be reproduced offline: forged and copied signature
  dictionaries, page-covering widgets, comments and empty signature fields
  after a signature, catalog swaps, untrusted, revoked or compromised time-stamp
  authorities, forged OCSP responders, CRLs out of scope or issued after expiry,
  removed signatures, decompression bombs in the DSS.
- pyHanko 0.38.1, used only as an external validator: B-B and B-T files
  (SHA-256 and SHA-512) valid with valid time-stamps, also countersigned and
  after a certification for form filling; DSS and document time-stamp updates
  rated "LTA updates", also after a P=1 certification; document time-stamps
  valid. With a test PKI (root, intermediate, signer, time-stamp authority,
  OCSP and CRLs answered in-process), only its root trusted, revocation data
  required and no online fetching: B-LT valid from the DSS alone, and B-LTA
  passed AdES LTA validation now and simulated 30 days later, after the signer's
  2-day certificate had expired. B-T without a DSS found no chain.
- `PdfSignatureVerifier` and pyHanko gave the same verdicts on a corpus of
  valid, tampered, certified-and-updated, countersigned and PKI B-LTA files,
  with two differences listed in the support policy. Files signed and
  countersigned by pyHanko verify as Valid.
- poppler's pdfsig judged the signatures valid; it does not recognise document
  time-stamps.
- Independent reviews: two rounds for PAdES signing, one for long-term data, and
  for verification two rounds by Claude agents and four passes by OpenAI Codex
  (gpt-6-astra) over the whole 7.10 range. Every finding was fixed or is listed
  below as a limit.

### Known limits

- Time-stamps (B-T, document time-stamps, their verification) need .NET 8 or
  later.
- `/VRI` entries are not written; intermediate certificates are added to a new
  signature's CMS only as far as the system's chain finds them
  (`AddValidationDataAsync` puts the rest in the DSS).
- A field whose seed value requires a time-stamp is still refused.
- The verifier does not check EU trusted lists, qualified status or signature
  policies, does not produce ETSI validation reports, does not verify
  RSASSA-PSS signatures on certificates, OCSP responses and CRLs, and does not
  inspect what the appearance streams of filled-in form fields draw. A visible
  empty signature field added after a signature leaves that signature
  Indeterminate until the field is signed.
- After a P=1 certification, an update that adds document information is a
  forbidden change for FreePDF (ISO 32000-2) while pyHanko accepts it.
- On .NET Framework and .NET Standard, the default client of
  `AddValidationDataAsync` checks addresses for HTTP only; HTTPS there needs
  `AllowPrivateNetworks` or your own `HttpClient`.

See the support policy (`../support-policy.md`).
