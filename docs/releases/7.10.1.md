# FreePDF 7.10.1

FreePDF 7.10.1 hardens reading, flattening and signature checking against
hostile files. It fixes cases where `PdfSignatureVerifier` reported a changed or
revoked signature as Valid, and it writes the right /Count for bookmarks.
Upgrade if you open PDFs from people you do not trust, in particular with the
verifier.

## Fixed: files that crashed the process

A stack overflow ends a .NET process; no exception handler stops it. Small files
built to nest deeply did that in every open mode, so also in
`PdfSignatureVerifier`. They now open, or fail with an ordinary exception:

- arrays and dictionaries nested inside each other: more than 256 levels is a
  parse error (`PdfReaderException`);
- a chain of streams whose /Length is the next stream: the chain is not
  followed, and the length is found from `endstream`;
- form field trees: more than 100 levels of fields with kids is refused when
  the file is opened (dropping them would hide fields from signature checks),
  and every walk up through /Parent stops at 100 fields and at a loop;
- outlines: items more than 200 levels deep are not read and stay in the file
  as they are;
- a filter array that holds itself, a cross-reference section full of `R`
  tokens, content arrays nested 50,000 levels (`ContentReader`), and XMP
  metadata nested more than 64 levels deep.

## Fixed: files that used gigabytes of memory or time

- Opening a file: the cross-reference and object streams decode to at most
  64 MiB each, and to at most 256 MiB or 64 times the file's size together.
  Every filter stage counts as it decodes, also what a predictor drops. The
  objects an object stream holds may span no more than the stream, and the
  objects, trailers and cross-reference streams of a file no more than twice
  the file. A few hundred bytes could inflate, or be read again, to gigabytes.
- The PNG predictor sizes its rows from the data, not from /Columns.
- XMP metadata is read only up to 16 MiB, one filter at a time.
- A content stream that ends inside a literal string ends the string there; the
  content lexer grew it until memory ran out.
- Flattening refuses a form whose values would make more than 64 Mi characters
  of new appearances (`InvalidOperationException`; the document is not
  changed). It adds its streams around the page content without decoding it,
  wraps multiline text in linear time, and names at most 10 fields in its
  messages.
- `PdfSignatureVerifier` reads earlier revisions one at a time, only where a
  revision ends, and throws `InvalidOperationException` beyond `MaxRevisions`
  revisions or `MaxSignatures` signatures (new options, 64 each). It does not
  answer when it cannot see every revision. Every byte it inflates from a DSS
  counts against a 64 MiB budget, and each DSS stream is inflated once. Form
  field names over 4,096 characters stop the permission check.

## Fixed: signatures reported Valid that were not

- **Changes to what a page draws.** An incremental update could change signed
  page content through an object that also had an exempt role: a field
  appearance that the page also drew through a nested form XObject, font,
  pattern or soft mask; a page's /CropBox number shared with a widget's
  appearance; resources shared with the document information or the DSS; an
  optional content configuration shared with the document information, rewritten
  to hide a layer. What a page draws (content, resources, boxes, rotation, also
  inherited ones) and the catalog's optional content properties and output
  intents are now walked to the end and get no exemption for later changes.
  Walks over what a signed field or an empty signature widget draws also go to
  the end.
- **Objects with two roles.** The exemptions for appearances, the document
  information and the metadata were checked before the rules for the catalog,
  the form and the pages, so a page-tree root also listed as a field's
  appearance could be replaced with one that adds a page (also in 7.10.0). A
  stream that a stamp shared with an editable field's appearance, or a stamp
  the form also listed as a field, passed as form filling. The structural rules
  now come first, and what an annotation draws may change only where
  annotations may. An exemption (an appearance, an annotation, the document
  information or metadata, validation data) now holds only for an object the
  document reaches through that role alone: an indirect /Kids array or a
  Hidden flag listed as an appearance could otherwise be changed.
- **Values that opening a file set.** The reader set some values when it opened
  a file. The signed revision and the whole file then had the same value, so an
  update that changed it was not seen (also in 7.10.0). These values were a
  text annotation's icon, a stamp's colour, the /Count of the page tree's root,
  and the /Parent of every page in a flat page tree. Such an update changes
  what a viewer shows: another icon or colour, possibly fewer pages, or,
  through a new /Parent, another crop box, rotation or resources for the page.
  PDFium, the engine of Chrome's viewer, showed a page with a new /Parent
  cropped and upside down while the signature stayed Valid under a "no
  changes" certification. The reader now leaves these values as the file has
  them: the icon and the colour in every mode, /Count and /Parent in Append
  mode.
- **Annotation order.** Annotations are drawn in the order of /Annots, but the
  order was not compared: a stamp moved after a filled-in field could cover it
  (also in 7.10.0). A new order now needs the annotation level.
- **Revocation data that cannot be used.** An OCSP response or CRL that FreePDF
  skipped (a filter or predictor it does not read, too large, unparsable,
  signed with RSASSA-PSS, from a responder it cannot find or does not trust, a
  delta CRL, a scope it cannot match) was dropped as if it said nothing, so a
  good answer of the other kind made a revoked signature Valid. Unread data now
  keeps the DSS from showing the certificate as not revoked, and a revoked
  answer that cannot be verified keeps the signature from Valid. A forged entry
  can now only make a result worse.
- **CRL and OCSP matching.** A CRL's issuer name is compared as RFC 5280 7.1
  says (string type, case, spaces, Unicode form), a CRL that lists the
  certificate and verifies with the issuer's key is the issuer's, and a listing
  CRL is never dropped for its scope. An OCSP issuer name hash matches either
  the certificate's issuer name or the issuer's subject (RFC 6960 4.1.1).
- **Signature fields.** An empty signature field whose `/FT /Sig` sat more than
  32 levels above its widget could draw over the signed page unreported. A
  visible empty signature widget with more than 10,000 appearance objects, or
  whose /Parent loops, now counts as changed. A limit refusal in an earlier
  revision's stream /Length was taken for a damaged revision and skipped, with
  any signature in it.

Also: a signed field whose `/FT` is on its parent field now counts as signed.
Its lock was ignored, and adding validation data made it Indeterminate.

## Fixed: bookmarks

Bookmarks with children get the /Count ISO 32000-1 12.3.3 requires. Open
bookmarks whose children were closed, and merged bookmarks, showed closed;
closed bookmarks never got their negative count. `PdfOutline.Opened` now reads
an opened file's state. An item read from a file keeps its /Count until it
changes, so Append-mode saves and the verifier see the file as written.

## Upgrading from 7.10.0

Update all FreePDF packages to 7.10.1 together and rebuild; the assembly
version is now 7.10.1.0. The public API gains
`PdfSignatureVerificationOptions.MaxRevisions` and `MaxSignatures`. Behaviour
changes to check:

- Files nested past the limits above, or whose structural streams decode past
  the budgets, throw `PdfReaderException` when opened.
- `PdfSignatureVerifier.VerifyAsync` throws `InvalidOperationException` for a
  file with more than 64 revisions or signatures (raise the options for files
  you trust) and for a file whose earlier revision exceeds the reader's limits.
- When the DSS holds an OCSP response or CRL that FreePDF cannot read, or a
  revocation it cannot verify, the DSS alone no longer shows the signer as not
  revoked: with `PdfRevocationCheck.Document` the signature is at best
  Indeterminate.
- A later update that changes anything a page draws is no longer allowed form
  filling, whatever else the changed object is.
- Opening a file no longer sets a text annotation's icon to Comment or a
  stamp's colour to yellow. A save keeps what the file has, so a text
  annotation without /Name keeps the default icon (Note).
- In Append mode the root of the page tree keeps the /Count of the file and a
  page keeps its /Parent, also when the file has them wrong.
- Flattening throws `InvalidOperationException` for forms over the appearance
  budget.
- Open bookmarks with closed children, and merged bookmarks, now show
  expanded.

See `docs/support-policy.md` for the limits and their known effects.

## Validation

All 7.10.0 release gates apply, plus:

- 1,231 regression tests in all (1,059 in 7.10.0). Each hostile file and each
  Valid-when-it-should-not-be case has a test that fails on 7.10.0 or on the
  commit before its fix. Two were not run against the old code, which would
  exhaust memory or need more than a million objects.
- Two tests list what the check of later changes still misses, and fail when a
  case is added or closed. One builds a file for every pair of a role that may
  change after a signature and a use that may not, signs it at every
  certification level and changes the object: 537 cells, 7 of them known (the
  first limit below), and 20 controls that show each role's own change is
  accepted. The other certifies six files with "no changes" and changes one
  value at a time: 2,998 changes, 17 of them not seen (the second limit
  below).
- PDFium 159.0.8149.0, poppler 25.03.0 and MuPDF 1.25.1, used only as external
  viewers for a page with a changed /Parent: PDFium takes what the page
  inherits from the node that /Parent names; poppler and MuPDF do not.
- Independent reviews: 26 static review rounds by OpenAI Codex (gpt-6-astra)
  over the hardening, then one more independent review, which added the two
  tests above and found the /Parent case. Every finding was fixed or is listed
  below as a limit.

### Known limits

The limits of 7.10.0 still apply. New, or newly known:

- The check of later changes assumes that an ordinary producer made the signed
  revision. A file that was built before signing so that one object has two
  roles can pass a later change to that object. Two cases are known: an array
  that is a page's /MediaBox and also its /Annots, and a bookmark that a form
  widget also lists as an appearance.
- The check does not compare the values that FreePDF still sets when it opens
  a file: the /Parent, /Prev and /Last of a bookmark, and the /SigFlags of a
  form that is an object of its own.
- Where no change after the signature is acceptable, require
  `CoversWholeFile`, or compare the revisions yourself.
- Actions and JavaScript are not judged for what they would show or hide when
  run.
- Streams other than cross-reference and object streams (page content, images,
  fonts) are decoded without a size limit when they are used. Process
  untrusted files with time and memory limits of your own. A limit is planned
  for 7.10.2.
- With `PdfRevocationCheck.Online`, a current answer from the issuer can show
  a certificate as not revoked next to DSS data that FreePDF could not read.
- A form widget with an array where an appearance belongs makes
  `PdfReader.Open` throw `ArgumentException`, not `PdfReaderException`.
- On .NET 8 on Windows, a DSS that lists a certificate stream without data
  makes the check fail, and the signatures of that file are Indeterminate.

See the support policy (`../support-policy.md`).
