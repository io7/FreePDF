# FreePDF 7.15.0

FreePDF 7.15.0 reads the text a page draws. `PdfTextExtractor` gives the text of
a page or a document, or each text run with its position, size and font.
`PdfLineExtractor` gives the straight segments of painted paths, such as table
rules. Both are new public API, so this is a minor version. No existing API
changes.

## Extract text

```csharp
using PdfSharp.Pdf.Content.Text;

using var document = PdfReader.Open("invoice.pdf", PdfDocumentOpenMode.Import);
string text = PdfTextExtractor.GetText(document.Pages[0]);          // reading order
string all = PdfTextExtractor.GetText(document);                    // pages end with "\f"
var runs = PdfTextExtractor.GetTextRuns(document.Pages[0]);         // text, baseline, size, font
var rules = PdfLineExtractor.GetLineSegments(document.Pages[0]);    // painted straight segments
```

The text of a character comes from the font's ToUnicode CMap. Without one, it
comes from the encoding: StandardEncoding, WinAnsiEncoding, MacRomanEncoding,
the Symbol and ZapfDingbats encodings and `/Differences`, with glyph names
mapped by the Adobe Glyph List. Composite fonts are read with Identity-H,
Identity-V or an embedded CMap, also one that inherits another CMap through
`/UseCMap`. Form XObjects, fonts set through `gs` and page resources inherited
from the page tree are read.

Reading order puts lines from the top down and runs from left to right. Content
order keeps the order of the content stream. Coordinates are in the page's
default user space. See [text extraction](../text-extraction.md) for what is
not yet read: predefined CJK CMaps, Unicode from embedded font programs,
`/ActualText`, annotations and form fields, rotated text and columns.

## Limits

`PdfTextExtractionOptions` bounds one page: `MaxDecodedBytes` (64 MiB),
`MaxFormDepth` (32) and `MaxResults` (1,000,000 runs or segments). Reaching a
limit throws `PdfReaderException`. `MaxDecodedBytes` counts each stream every
time it is read, the extracted text at two bytes per character and the tables
built for fonts, so a page can use about 4,000 fonts. There is no time limit:
extract text from untrusted PDFs in a separate process with memory and time
limits.

A syntax error ends that content stream and keeps the text before it. A stream
whose filters fail on its data draws nothing. A stream with a filter that
FreePDF does not implement, such as RunLengthDecode, throws
`NotImplementedException`, so text is not lost without notice.

## Documentation

FreePDF now has a guide to the drawing API and an API reference:
https://io7.github.io/FreePDF/. Every example in the guide is a test that CI
runs. The package readme links the site, and the XML comment of
`PdfDocumentOpenMode.Append` no longer says that encrypted documents and nested
page trees are not supported (both work since 7.5.0 and 7.7.0). These are the
only package changes since the 7.15.0 version commit; there is no code change.
The packages were built from commit 1953786.

## New notice in every package

Every package carries `THIRD-PARTY/Adobe-Glyph-Tables.txt`. It holds the
notices of the Adobe Glyph List, the ITC Zapf Dingbats Glyph List and Adobe's
Core14 AFM data. `eng/update_text_tables.py` generates the glyph tables from
these sources, and pins each one by SHA-256.

## Upgrading from 7.14.1

When your NuGet source lists 7.15.0, update your FreePDF packages together and
rebuild for assembly version `7.15.0.0`. The accessibility tool is unchanged
apart from its version. To update a global installation, use this command.

```sh
dotnet tool update --global io7.FreePDF.Accessibility.Tool --version 7.15.0
```

## Validation

All 7.14.1 release gates apply, plus:

- 1,400 regression tests in all (1,334 in 7.14.1). The 66 new tests build their
  PDFs in code: hand-made fonts and CMaps, FreePDF's own XGraphics and MigraDoc
  output, forms, damaged content and the limits. Four hostile fonts run in a
  child process with a 256 MiB heap and a 10-second budget.
- The synthetic corpus checks FreePDF's own text against each case's lines, as
  it checks Poppler's `pdftotext`. The smoke tier passed 180 of 180 PDFs from
  the FreePDF, ReportLab and Chromium producers.
- Three independent static reviews by OpenAI Codex (gpt-6-astra). The first two
  found 22 defects. 21 are fixed, each with a test that fails without the fix.
  The third review found no regressions. One finding was declined: a number
  written directly before a keyword (`0Tf`) is read as a number and an
  operator, not as one unknown keyword.
