# FreePDF 7.7.0

FreePDF 7.7.0 adds, removes and moves pages in `Append` mode when the page tree
is nested, keeps the page attributes of new and moved pages right, accepts every
XMP packet header the XMP specification allows, and fixes how metadata is
handled in encrypted documents.

## New

- **Page changes in nested page trees.** In a document opened with
  `PdfDocumentOpenMode.Append`, `Insert`, `Remove`, `RemoveAt`, `MovePage`,
  `InsertRange` and `PdfDocument.AppendPages` now work when the page tree has
  intermediate nodes. They threw `NotSupportedException`. The update changes the
  tree where it is and writes only the nodes between the root and the pages that
  come or go:
  - A page goes next to its neighbours in their node. The node the page was in
    when the file was opened comes first, so a page moved within its node stays
    in it. A page at either end with no such node goes into the root.
  - `/Count` is adjusted up to the root. Removing a page also takes out the
    highest node left without pages, unchanged, so that node is not written.
  - A page moved under another node keeps its media box, crop box and rotation.

  A certification signature (DocMDP) refuses page changes as before.

## Fixed

- **Inherited page attributes of new pages.** In `Append` mode, a new page took
  the crop box, rotation or resources of the page tree node it went into, also
  when the root of a flat tree had them. In `Modify` mode, a new page took those
  values, and the media box, from the root of the opened file. A new page under a
  node with `/Rotate 90` came out rotated, for example.
- **Re-inserting a page.** A page taken out with `Remove` or `RemoveAt` can be
  inserted again; `Insert` threw "Object already in table".
- **Rotation and boxes in the page tree.** A `/Rotate` inherited as an indirect
  object, or as a real number, was ignored. A page whose own media box or crop
  box is an indirect object could not be opened ("PdfRectangle is not implemented
  as an array") under a node that also has one. A box or rotation that refers to
  a null object now counts as missing, so the page inherits the node's.
- **`AppendPages` and the catalog.** `AppendPages` added an empty outline to the
  catalog even with no bookmarks to merge. In `Append` mode that was a change to
  the catalog.
- **XMP packet headers.** `PdfMetadata.SetMetadata(string)` threw "Unknown
  metadata encoding tag" for a header in single quotes, and for a begin attribute
  that holds the byte order mark U+FEFF, as XMP read from a file into a string
  has it. A cut-off header throws `InvalidOperationException` instead of
  `ArgumentOutOfRangeException`.
- **`SetMetadata` on compressed metadata.** `SetMetadata` kept the filters of
  the old content, so `SetMetadata(ToString())` on compressed metadata wrote
  plain XML under `/FlateDecode`, which no reader could decode. Only the crypt
  filter stays, because it says whether the stream is encrypted.
- **Unmarked document metadata.** With `EncryptMetadata` false, a `Modify` save
  that keeps the encryption (`PdfReaderOptions.DoNotResetEncryption`) marks the
  document's metadata with the Identity crypt filter, as a save that resets the
  encryption does. Metadata that another writer left unmarked stayed unmarked,
  and pyHanko and MuPDF tried to decrypt the plain XML. Metadata that names
  another crypt filter stays encrypted with it, in this save and in `Append`
  mode.
- **Re-encrypted files that could not be opened.** Encrypting a document again
  with `EncryptMetadata` true, when the opened file had it false, kept
  `/EncryptMetadata false` in the new encryption dictionary. For V4, readers then
  computed another key, and no one could open the file with its password.
- **Crypt filters in older and unusual layouts.**
  - An `Append` save of an RC4 file with encryption version 1 to 3 whose
    encryption dictionary still says `/EncryptMetadata false` threw "Crypt filters
    are not supported" when the document's metadata changed.
  - Crypt filter parameters held by reference inside a `/DecodeParms` array are
    read.

## Upgrading from 7.6.1

Update all FreePDF packages to 7.7.0 together and rebuild; the assembly version
is now 7.7.0.0. The public API is unchanged. Behaviour changes to check:

- Page changes in `Append` mode on nested page trees are saved instead of
  throwing.
- In `Modify` mode, the root of the page tree no longer holds the inheritable
  values (`/Resources`, `/MediaBox`, `/CropBox`, `/Rotate`) it had in the opened
  file, because every page holds them.
- In `Append` mode, a new page under a node or root that has a rotation or crop
  box gets an explicit `/Rotate 0` or crop box in the update.
- `SetMetadata(byte[])` takes plain XML and drops `/Filter`, `/DecodeParms` and
  `/DL` from the old content, except the crypt filter.
- `SetMetadata(string)` accepts only encoding names in the begin attribute, as
  `ToString` writes them. A number or a list of names throws.
- Metadata that names an encrypting crypt filter while `EncryptMetadata` is false
  stays encrypted. MuPDF and FreePDF read such V4 files. pyHanko 0.29.1 does not,
  because it decrypts explicit crypt filters in streams with the file key
  instead of the per-object key (ISO 32000-1 7.6.2).
- pyHanko's difference analysis reports any page change after a signature, on
  flat and nested trees alike, as the migration guide describes.

## Validation

All 7.6.1 release gates apply, plus:

- 58 new regression tests, 723 in all:
  - nested page trees: inserting, removing, moving and merging pages; the objects
    each update writes; `/Count` and `/Parent` stay consistent; inherited values
    of new and moved pages; moving a page and moving it back saves the original
    bytes; refusals under a certification;
  - XMP headers in either quote style, with and without U+FEFF;
  - marking document metadata, and keeping explicit crypt filters, for V4-RC4,
    AES-128 and AES-256;
  - re-encryption with `EncryptMetadata` true;
  - `SetMetadata` on compressed metadata.
- Nested-tree files signed with pyHanko 0.29.1 were edited in `Append` mode:
  - an insert with drawing, a move, a removal, a merge and a FreePDF
    countersignature;
  - poppler and MuPDF report the expected size, crop box and rotation for every
    page;
  - pdfsig reports every signature valid.
- A file that pyHanko certified with "form filling" (P=2) refuses the insert
  before anything is written.
- pyHanko and mutool read the document metadata of V4-RC4, AES-128 and AES-256
  files whose metadata was left unmarked, after a `Modify` save with
  `DoNotResetEncryption`.
- Independent reviews (two rounds for the page tree change, three for the
  metadata fixes) found issues, which were fixed before release.
