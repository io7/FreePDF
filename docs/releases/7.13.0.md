# FreePDF 7.13.0

The native accessibility scanner now follows reusable pieces of page content
called Form XObjects, including forms drawn inside other forms. Both the
`PdfAccessibilityScanner.Scan` API and the `freepdf-a11y` tool check this content.

## Find a problem inside a form

```sh
freepdf-a11y document.pdf --format json --output audit.json
```

Findings identify the page and the resource path to the form, for example
`/Resources/XObject/Outer/Resources/XObject/Inner`. The scanner checks whether
painting is tagged or marked as an artifact, whether fonts used for visible text
are embedded, and whether each marked-content ID refers to the right structure
element. It also resolves named marked-content properties in the active resources.

A page and a form can each use marked-content ID `0`. If the document draws the
same form twice and that form owns marked-content IDs, FreePDF reports
`FPDF-A11Y-MCID`. In the `reused-tagged-form` test, drawing the outer form twice
also draws its tagged inner form twice. FreePDF reports the repeated use and
veraPDF 1.30.3 passes its machine checks on that file. The combined report
includes both results and the CLI exits with `1`.

The native checks cover part of PDF/UA-1. Reading order and the meaning of
alternative text still need human review. See the [preflight guide](../accessibility-preflight.md)
and the [veraPDF test cases](../accessibility-verapdf.md#validation).

## Upgrading from 7.12.0

The tool requires .NET 10. When your NuGet source lists 7.13.0, update an
existing global installation with this command.

```sh
dotnet tool update --global io7.FreePDF.Accessibility.Tool --version 7.13.0
```

If your application uses the FreePDF libraries, update its FreePDF packages
together and rebuild for assembly version `7.13.0.0`.
