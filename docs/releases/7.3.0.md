# FreePDF 7.3.0

FreePDF 7.3.0 merges and splits documents without losing their form fields,
bookmarks and links, and names FreePDF, not PDFsharp, as the producer of the
files it writes.

## New

- **Merge and split with forms, bookmarks and links.** Merging with PDFsharp
  6.2.4's `output.AddPage(input.Pages[i])` copies the widgets of a form but not
  the form, so the merged fields stop working; it drops the bookmarks; and a link
  to another page leads to a hidden copy of that page, which also comes along
  when you split. The new methods keep all three:

  ```csharp
  merged.AppendPages(source);                         // all pages
  merged.AppendPages(source, startIndex, pageCount);  // a range
  merged.AppendPages(source, new PdfPageImportOptions { BookmarkTitle = "invoice.pdf" });
  using var part = source.ExtractPages(startIndex, pageCount);
  ```

  - Form fields with a widget on a copied page join the document's form and can
    be filled or flattened, with the font, size and colour their own form gave
    them. A field whose name is already used becomes `name_2`, `name_3` and so
    on; `AppendPages` returns the new names in `RenamedFields`. To merge filled
    forms into a file that cannot be edited, call `Flatten()` on the result.
  - Links, the GoTo actions of buttons, and bookmarks lead to the copied pages.
    Named destinations are written as the explicit destinations they name. Those
    that lead to a page that was not copied are removed; those that lead
    elsewhere, such as a web address, are kept. `BookmarkTitle` puts each
    source's bookmarks under one bookmark.
  - A split file carries no hidden copies of the pages it left out. Fonts and
    images are shared between the copied pages, their annotations and repeated
    copies of the same source.
  - The pages keep their transparency group, tab order and user unit, which
    `AddPage` drops.
  - If copying fails on a damaged source, the document's pages, form and
    bookmarks are left as they were.

  `AddPage(page)` and `Pages.InsertRange` keep 6.2.4's behaviour.
- **FreePDF as the producer.** Saved documents say `FreePDF 7.3.0+<commit>` as
  their Producer and, by default, `FreePDF 7.3.0+<commit>
  (https://github.com/io7/FreePDF)` as their Creator; documents from the layout
  engine say `FreePDF Layout`. The XMP metadata, the file's closing comment and
  a signature's default application name follow. Up to 7.2.0 they said
  `PDFsharp 7.2.0` and `empira MigraDoc`, which read like empira's AGPL
  PDFsharp 7. Saving a file another PDFsharp version wrote records FreePDF as the
  Producer and keeps the old value as the original.

## Fixed

- An annotation whose `/Subtype` is a number made the whole document
  unreadable. It is now read as an unknown annotation.
- A bookmark colour outside 0 to 1, which some producers write as 0 to 255,
  threw `ArgumentException` when the outline was read. It is clamped, and
  colours are rounded so that they read back as written.

## Upgrading from 7.2.x

Update all FreePDF packages to 7.3.0 together and rebuild; the assembly version
is now 7.3.0.0. Behaviour changes to check:

- Code or tests that recognise their own output by a Producer starting with
  "PDFsharp", or compare it with `PdfSharpProductVersionInformation.Title`,
  should expect "FreePDF". The `PdfSharpProductVersionInformation` and
  `MigraDocProductVersionInformation` constants now name FreePDF and io7;
  empira's copyright is kept.
- Bookmark colours are rounded instead of truncated, so a colour read from a
  file can differ by one unit from 7.2.0.

`AppendPages` and `ExtractPages` are new; existing merge code is unchanged until
you switch to them. Not carried: tags (the structure tree), page labels, optional
content (layer) settings, XFA, and named destinations as names. Append each
source in one call: pages appended in separate calls are separate copies.
Copied signatures cannot be valid in the new file.

## Validation

All 7.2.0 release gates apply, plus:

- regression tests for merging and splitting (form fields, renames, each
  form's appearance, flattening after a merge, links, button actions,
  bookmarks, shared fonts, hidden pages, damaged entries) and for the producer
  identity; 435 regression tests in all;
- every file of a 2,950-file veraPDF and producer corpus that opens (2,943) was
  appended twice and had its first three pages split off one at a time, then
  saved and reopened, without errors;
- an independent review of the merge and split code, whose findings were fixed
  or documented before release.

See the migration guide's "Merging and splitting" section (`../migrating-to-7.md`)
and the support policy (`../support-policy.md`).
