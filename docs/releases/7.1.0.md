# FreePDF 7.1.0

FreePDF 7.1.0 makes the move from PDFsharp 6.2.4 easier, publishes the Windows
GDI and WPF builds, adds Factur-X / ZUGFeRD invoices and tagged PDF/UA-1 output
from the layout engine, and fixes the defects that a round trip over 2,950 real
PDFs and two mutation fuzzing campaigns found.

## Coming from PDFsharp 6.2.4

- 23 of 26 public PDFsharp 6.2.4 projects compile against FreePDF unchanged
  (`../research/consumer-survey`). Restored 6.2.4 members:
  `DictionaryElements.GetDateTime(string, DateTime)`, the parameterless
  `CString`, `CInteger` and `CReal` constructors and `PdfDocument.SetPdfA()`.
  The migration guide lists what the other three needed.
- New packages for Windows desktop and .NET Framework applications:
  `io7.FreePDF.Gdi`, `io7.FreePDF.Layout.Gdi`, `io7.FreePDF.Wpf` and
  `io7.FreePDF.Layout.Wpf`, for Windows .NET 8, 9, 10 and .NET Framework 4.6.2.
  They replace `PDFsharp-GDI`, `PDFsharp-MigraDoc-GDI`, `PDFsharp-WPF` and
  `PDFsharp-MigraDoc-WPF` and keep upstream's assembly names.

## New

- **Factur-X / ZUGFeRD hybrid invoices.** `FacturXManager.SetInvoice(xml,
  profile)` embeds a Cross Industry Invoice and declares it for Factur-X 1.0 /
  ZUGFeRD 2.x on PDF/A-3b. FreePDF checks that the XML is a well-formed Cross
  Industry Invoice; validating its content is up to your invoicing software.
- **Tagged PDF/UA-1 from the layout engine.** `PdfDocumentRenderer.TaggedPdf`
  tags headings, paragraphs, lists, tables, images, charts and links, and marks
  headers, footers and decoration as artifacts. `Shape.AlternativeText` and
  `Shape.Decorative` describe images and charts. Rendering stops with an
  explanation instead of writing a non-conforming file. Core additions:
  `StructureBuilder.SetScope`, `BeginLinkElement` and `AddLinkAnnotation`; XMP
  metadata declares PDF/UA-1 for every tagged document.
- **16-bit PNG images** are imported (embedded with 8 bits per component).

## Fixed (a selection; `../../CHANGELOG.md` lists all)

- A new document that read `document.Outlines` without adding an item saved a
  file FreePDF itself could not reopen.
- Encrypted files whose trailer holds the encryption dictionary directly, as
  MuPDF writes them, opened without asking for the password.
- Real files that failed to open: annotations of unknown subtypes, streams with
  external file data, PDF 2.x minor versions, a dangling `/Info`.
- Damaged files fail with `PdfReaderException` instead of other exception types,
  and no longer loop until memory runs out or destroy the catalog while opening
  or saving.
- `Document.Clone()` returned a copy bound to the original's renderer.
- The BMP importer's file-size check was inverted, which broke images drawn
  from GDI+ and WPF bitmaps.
- `PdfAFormats.PdfA_2u` described PDF/A-2b.

## Upgrading from 7.0.1

Update all FreePDF packages to 7.1.0 together and rebuild; the assembly version
is now 7.1.0.0. Behaviour changes to check:

- `/Annots` entries that are not dictionaries are dropped when a document opens,
  so `PdfPage.Annotations` holds only annotations.
- A document without a page tree is refused with `PdfReaderException`; it used
  to open as an empty document whose save dropped every page.
- A page without a usable `/MediaBox` reads as US Letter, as Poppler and MuPDF
  show it, and gets that box on save.
- A `null` or dangling dictionary entry reads as absent in typed reads, and an
  object that already has an unrelated type is not converted again.

## Validation

All 7.0.1 release gates apply, plus the GDI and WPF package consumers on
Windows, a Factur-X invoice validated as PDF/A-3b and a tagged three-page invoice
validated as PDF/UA-1 by veraPDF, and 349 regression tests. The corpus round
trip and the fuzzing campaigns are documented in
`../research/corpus-roundtrip-2026-11.md`. The support policy states what the
new features cover; see `../support-policy.md`.
