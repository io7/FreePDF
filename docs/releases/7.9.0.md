# FreePDF 7.9.0

FreePDF 7.9.0 draws the barcodes invoices, labels and tickets need (QR, Data
Matrix, Code 128, EAN and UPC) as vector shapes, renders MigraDoc barcode
elements, and creates fillable form fields, so the whole form cycle is covered:
create, fill, flatten, merge, sign and certify. It also extracts text beyond
U+FFFF correctly and fixes two MigraDoc tab problems from the upstream triage.

## New

### Barcodes

- **QR codes.** `CodeQR` draws model 2 QR codes, versions 1 to 40, error
  correction levels L, M, Q and H, as one vector path. The smallest version that
  fits is chosen unless `Version` is set; digits and upper-case text use the
  compact numeric and alphanumeric modes; other text is UTF-8, marked with
  ECI 26 unless `Utf8Eci` is false. `GetModules()` returns the module matrix for
  custom drawing.
- **Data Matrix.** `CodeDataMatrix` has a new ECC 200 encoder written from
  ISO/IEC 16022 and draws vector modules in every build: all 30 sizes, square and
  rectangular, the smallest square chosen when rows and columns are 0, ASCII
  encodation (with ECI 26 for text that is not ASCII, FNC1 for GS1 DataMatrix) and
  Base256.
- **Code 128.** `Code128` picks code sets A, B and C for the shortest code and
  supports GS1-128 through `Code128.Fnc1`, a private-use character (U+E0F1).
- **EAN-13, EAN-8 and UPC-A.** `Ean13`, `Ean8` and `UpcA` add or check the check
  digit and draw the digits under the bars with long guard bars. `CodeType` and
  `BarCode.FromType` know the new codes.
- **MigraDoc renders barcodes.** `Barcode` elements were silently left out of
  the PDF. They now draw 2 of 5, Code 39, Code 128 and the new `BarcodeType`
  values Ean13, Ean8, UpcA, QRCode and DataMatrix, rotated by `Orientation`, with
  text in the Normal style's font when `Text` is set. The shape's size includes
  the quiet zones. `Section`, `Cell`, `TextFrame` and `HeaderFooter` get
  `AddBarcode()`. The RTF renderer leaves barcodes out with a warning.

### Forms and signatures

- **Creating form fields.** `PdfForm.AddTextField`, `AddCheckBox`,
  `AddRadioButtonGroup`, `AddComboBox`, `AddListBox` and `AddSignatureField`
  place a field on a page, with its rectangle in drawing coordinates (points from
  the top left of the visible page, as for `XGraphics`) and an appearance every
  viewer shows. `PdfFormFieldStyle` sets the font size, colors, border,
  alignment and tool tip. Created fields can be filled, flattened, merged and
  signed like fields read from a file.
- **Certifying a document.** `DigitalSignatureOptions.Certification` makes the
  signature a certification signature (DocMDP) that permits no changes, form
  filling, or form filling and comments. Only the first signature of a document
  can certify it, and FreePDF's Append mode enforces the level it wrote.
- **Seed values naming the signature type.** A signature field whose seed value
  names the signature type (/MDP) can now be signed: an approval signature where
  /P is 0, a certification at the named level where /P is 1 to 3.

## Fixed

- **Text beyond U+FFFF.** Emoji and mathematical letters were extracted wrongly:
  the ToUnicode map wrote their code points raw instead of as UTF-16 surrogate
  pairs. Maps with more than 100 glyphs are now split into sections of at most
  100, as CMaps require.
- **MigraDoc default tab stops** reach the right edge of the text. They were
  missing in the last part of each line as wide as the left margin, so a tab
  there broke the line.
- **MigraDoc blank after a tab.** A blank right after a tab made the tab break
  the line although the following text fitted.
- **Data Matrix.** The inherited encoder drew nothing in the Core build, lost the
  last one or two characters in C40, Text and X12, and wrote unreadable EDIFACT
  symbols. It appears to derive from the GPL-licensed iec16022 library and carried
  no notice of that origin; it is removed and replaced (see `PROVENANCE.md`).
- **Low-bit PNG.** 1-, 2- and 4-bit grayscale and 2-bit palette PNGs load in the
  Core build; they threw "Unsupported bit depth". QR code generators often write
  1-bit grayscale.
- **Signatures.** `DigitalSignatureOptions.ContactInfo` is written; it was
  ignored. A signature into a locked field that also certifies keeps both
  signature references.
- **Smaller fixes.** Code 39 refuses an apostrophe, which has no bar pattern
  (drawing threw `IndexOutOfRangeException`); saving a document as DDL escapes
  quotes, backslashes and line breaks in a barcode's code.

## Upgrading from 7.8.0

Update all FreePDF packages to 7.9.0 together and rebuild; the assembly version
is now 7.9.0.0. The public API only gains members. Behaviour changes to check:

- MigraDoc documents with `Barcode` elements now draw them. A code that is
  invalid for its type now makes rendering throw, and with `TaggedPdf` a barcode
  needs `AlternativeText` or `Decorative`, as images and charts do.
- Data Matrix requests for C40, Text, X12 or EDIFACT are written in ASCII
  encodation, so a fixed size can now be too small for text that used to
  (wrongly) fit.
- A signature field with a seed value /MDP was refused; it is now signed when
  `Certification` matches it, and refused with an `ArgumentException` when it
  does not.
- MigraDoc lines with tabs near the right edge, or a blank after a tab, can be
  laid out differently.

## Validation

All 7.8.0 release gates apply, plus:

- 124 new regression tests, 962 in all. The MigraDoc tab tests were checked to
  fail without their fix.
- Barcodes: tests read symbols with readers written from the standards; the QR
  "HELLO WORLD" 1-M codewords and the ISO/IEC 16022 "123456" encodation example
  match. zxing-cpp 3.1.1, used only as an external decoder, read every QR
  version 1 to 40 at every level and mode at full capacity (1,004 symbols), Data
  Matrix at all 30 sizes at full capacity and with Latin-1, UTF-8, GS1 and
  Base256 data (212 symbols), the linear codes, codes drawn by MuPDF and poppler,
  and MigraDoc barcodes with borders. A strict checker written from ISO/IEC 16022
  passed 305 Data Matrix symbols.
- Forms: MuPDF and pypdf read the type, value and on states of every created
  field in new, filled and reopened-then-filled files, and MuPDF and poppler
  rendered them. pyHanko 0.6.0 read certification levels 1 to 3 from FreePDF's
  files as VALID and judged filling text fields, check boxes and combo boxes
  after certification at levels 2 and 3 as permitted. Its default policy rejects
  selecting a radio button after a certification, also when pypdf writes the
  same two-object update; the support policy lists this with the other places
  where pyHanko is stricter than the permissions.
- Text: poppler and MuPDF extract U+1D400, U+1F600 and 150 Latin Extended
  letters from a file written with an original test font; 22 MigraDoc documents
  were compared word by word with 7.8.0, with changes only where intended.
- Independent reviews (two rounds for barcodes, one each for forms and the text
  fixes) found issues, including a regression in a tab fix, which were fixed
  before release.

### Known limits

- Text and choice fields use Helvetica, which is not embedded, so PDF/A
  documents refuse them; check boxes, radio buttons and signature fields work in
  PDF/A. Fields are not tagged yet, so tagged (PDF/UA) documents refuse them.
- Fields cannot be added to rotated pages; there are no push buttons and no
  MigraDoc form elements yet.
- MigraDoc QR codes use level M; `BearerBars`, `NarrowLineWidth` and
  `LineHeight` are not used.
- A printed code's readability also depends on its size, contrast, quiet zone
  and print quality.
- Colour emoji drawn with `XPdfFontOptions.ColoredGlyphs` still extract as their
  layer glyphs.
