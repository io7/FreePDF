# FreePDF 7.1.1

FreePDF 7.1.1 places text in filled form fields exactly where a PDF viewer
places it. Nothing else changes from 7.1.0.

## Fixed

- Form fields usually name a standard font such as Helvetica (`/Helv`) without
  listing its character widths. 7.1.0 estimated those widths, so centred,
  right-aligned, wrapped and auto-sized text could land a few points off; 7.1.1
  uses Adobe's metrics for the twelve Latin standard fonts (Helvetica, Times and
  Courier with their bold and italic styles). Arial, Times New Roman and Courier
  New use the metrics of Helvetica, Times and Courier, with which they share
  widths. Left-aligned single-line text was already placed exactly.

## Third-party notice

The widths come from Adobe's Core14 AFM files. Adobe's terms allow their use and
redistribution if the copyright notices and Adobe's paragraph are kept and
modifications are noted. Each package now carries them as
`THIRD-PARTY/Adobe-Core14-AFM.txt`; `../../PROVENANCE.md` records the source and
the SHA-256 pinning of every input.

## Upgrading from 7.1.0

Update all FreePDF packages to 7.1.1 together and rebuild; the assembly version
is now 7.1.1.0. The public API is unchanged. Filled form fields drawn with
centred, right-aligned, multi-line or auto-sized text get slightly different,
correct positions and font sizes.

## Validation

All 7.1.0 release gates apply, plus a check of every width against Adobe's files
and regression tests that place right-aligned text in Helvetica, Arial Bold, a
subset Times New Roman and an unknown font; 383 regression tests in all.
