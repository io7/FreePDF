# FreePDF 7.0.0

FreePDF's first stable release continues the verified MIT PDFsharp/MigraDoc
source, with original copyright notices and source history preserved. It adopts
MIT v7 Preview 1 and adds independently reproduced correctness fixes. Later AGPL
PDFsharp implementations were not used as implementation inputs.

## Packages

- `io7.FreePDF`: PDF creation, reading, modification, drawing, barcodes, charts
  and cryptography.
- `io7.FreePDF.MigraDoc`: paragraph/table layout and PDF/RTF output; depends on
  `io7.FreePDF`.

Both packages contain .NET 8, 9, 10 and Standard 2.0 assets. Windows Framework
4.6.2/4.7.2 consumers use the Standard assets on a maintained Framework runtime.
Use a patched .NET 10 runtime for new applications. GDI/WPF remain source builds.

## Correctness and validation

Corrections cover complete zlib streams, graphics-state restoration, disconnected
paths, merged tables, font caching/subsetting, indexed PNG alpha, bounded malformed
input, inherited page properties, hybrid and incremental cross-reference reading,
shared content ownership, signature naming and partial-stream signing reads.

Release gates include 191 modern .NET regressions, 185 Framework regressions,
44 public API comparisons, installed-package workflows, dependency/advisory
audits, independent qpdf/Poppler/veraPDF validation and 23 comparison cases.
Known defects in the reference remain visible reviews, not a claim that every
output should match the reference. See `../7.0.0-validation.md` for evidence scope.

## Migration and limits

The namespaces and assembly names remain `PdfSharp` and `MigraDoc`. Remove
upstream package references and rebuild; v6 binary compatibility is not promised.
Configure an application-owned font resolver. Read `../migrating-to-7.md` and
`../support-policy.md` before upgrading.

Saving rewrites PDFs and does not preserve existing signatures or perform
incremental saving. General typed form filling/flattening, PDF/UA, complex-script
shaping, arbitrary PDF/A conversion, PAdES/LTV and FIPS certification are outside
the release claims. PDF/A conformance and CMS integrity checks apply to the
authored fixtures; validate your application's own output separately.

The exact package hashes and source revision accompany the release artifacts.
These notes describe the prepared release; public availability is established by
the published GitHub release and NuGet listings.
