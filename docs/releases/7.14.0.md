# FreePDF 7.14.0

The accessibility scan now stays within firm memory and time bounds on hostile
PDFs. A new `MaxDuration` limit ends a scan that runs too long, and
`freepdf-a11y` sets it with `--timeout`.

## Set a time limit

```sh
freepdf-a11y document.pdf --timeout 60 --format json --output audit.json
```

```csharp
var options = new PdfAccessibilityScanOptions { MaxDuration = TimeSpan.FromSeconds(60) };
var report = PdfAccessibilityScanner.Scan("document.pdf", options);
```

The default is 2 minutes in the API and 120 seconds in the CLI. Set
`MaxDuration` to `null` for no limit. When the limit is reached, the report is
`Incomplete`, keeps the failures found so far and says
`Scan exceeded MaxDuration.` Opening the PDF is not interrupted by the limit;
use the cancellation token for that.

## Memory and time on hostile files

- The scanner reads page and form content one operator at a time. A 20 KB file
  whose content decompresses to 20 MB of `q` operators used 2.4 GB in 7.13.0
  and now uses about 150 MB.
- Equal consecutive saved graphics states share one entry. More than 65,536
  distinct saved states make the scan incomplete.
- XMP metadata nested deeper than `MaxDepth` is not checked, and the
  declaration and title checks look at each element once. A 124 KB file with
  nested `pdfuaid:part` elements used 382 MB and now uses about 50 MB.
- A whitespace-only `/Alt` shared by many structure elements, the MCIDs of a
  form drawn many times and a `/CharProcs` dictionary shared by Type3 fonts are
  each checked once. Files of about 1.3 MB took 1 to 3 seconds in 7.13.0 and,
  within the default limits, up to an hour.

The tests scan nine hostile inputs in a separate process with a 256 MiB .NET
heap limit and a 20-second `MaxDuration`. Each input must give its expected
result. These limits cover the known cases, not every possible file, so scan
untrusted PDFs in a separate process with memory and time limits.

## Changed results

- A failure found in content before a parse error is now kept. The scan is
  `Incomplete` and the CLI exits with `1` instead of `3`.
- A form drawn several times on one page reports a missing MCID once instead of
  once per drawing.
- A scan whose `MaxDuration` ran out is never reported as completed.

See the [preflight guide](../accessibility-preflight.md) for all scan limits.

## Upgrading from 7.13.0

The tool requires .NET 10. When your NuGet source lists 7.14.0, update an
existing global installation with this command.

```sh
dotnet tool update --global io7.FreePDF.Accessibility.Tool --version 7.14.0
```

If your application uses the FreePDF libraries, update its FreePDF packages
together and rebuild for assembly version `7.14.0.0`. A scan that used to run
longer than 2 minutes now ends as `Incomplete`; set `MaxDuration` to a larger
value or to `null` if you need the old behaviour.
