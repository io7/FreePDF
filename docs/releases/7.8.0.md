# FreePDF 7.8.0

FreePDF 7.8.0 opens damaged files that viewers open, fixes MigraDoc documents
that crashed or never finished rendering, and keeps PDF/A files conforming: CID
fonts get the CIDSet PDF/A-1 requires, and the XMP metadata of generated and
opened files agrees with the document information. The fixes come from a triage
of the upstream PDFsharp issue tracker; each was written from the issue
description and an original reproducer.

## New

- **Rebuilding unreadable cross-reference information.** A file whose
  cross-reference table or stream cannot be read (a wrong `startxref`, offsets
  that point elsewhere, a missing table, a damaged cross-reference stream) is
  rebuilt from its objects, as viewers do, instead of being refused:
  - each object header outside stream data, strings and comments gives a
    position, and the newest copy of an object wins;
  - object streams supply their objects (not in encrypted files);
  - `/Root`, `/Info`, `/ID` and `/Encrypt` come from the newest trailer or
    cross-reference stream dictionary that names a `/Root`;
  - the work grows linearly with the file size, also on hostile input.

  `Append` mode still refuses a rebuilt file, because an incremental update
  needs the original cross-reference information.

## Fixed

### Reading files

- **Stream lengths.** `endstream` was searched for only 20 bytes past where
  `/Length` says a stream ends, so padded streams (as IBM i invoice generators
  and Bluebeam write them) and much too short lengths stopped the whole file
  opening ("Cannot retrieve stream length"). The search now covers the bytes up
  to the next object. A correct length followed by padding is kept; otherwise
  the `endstream` nearest the declared end that closes the object is taken, and
  the line break before it is no longer part of the data.
- **Objects an update gives an old number.** An incremental update that gives a
  new object the number of an older revision's cross-reference stream lost the
  newer object, so a form could vanish and a `Modify` save dropped it.
- **Importing indirect page attributes.** Importing a page whose `/Rotate`,
  media box or crop box is an indirect object, as pdf-lib writes it, threw in
  `AddPage`, `InsertRange` and `AppendPages`.
- **Further reading fixes.** A `startxref` far from the end of the file is found
  without reading the file into one string; a reference with an object number
  beyond the PDF limit reads as null; an object without `endobj` is read; a `)`
  outside a string is skipped; the LZW decoder no longer loses a byte when a code
  names the table entry being defined; a stream that returns fewer bytes per read
  than asked for is no longer taken for a file that is not a PDF.
- **Names in content streams.** Names with bytes above 127 are decoded like names
  in the file (UTF-8 first, then the current ANSI code page), so a Shift-JIS or
  GBK font name in a content stream matches its resource key.

### MigraDoc

- **Justified paragraphs that never finished.** A justified paragraph with a tab,
  such as a list item, and soft hyphens sent rendering into an endless loop.
  Justified lines with a tab or a field are also spaced correctly now: words
  could overlap, jam together or run past the right margin.
- **Bordered paragraphs at a page bottom.** An empty paragraph with a bottom
  border, or one ending with a line break, threw "'Rectangle' must not be null
  here" when its last line fitted at the bottom of a page but its border did not.
  It now ends on the next page.
- **`KeepWith` past the last row** threw `ArgumentOutOfRangeException`; the row
  now keeps with the rows up to the end of the table.
- **Charts without axis settings.** A column, line or area chart whose code sets
  no Y axis property threw "'Axis' must not be null here"; it is drawn without a
  value axis, as bar charts already were. A chart whose code sets no X axis
  property drew its columns, bars or line at NaN coordinates, which viewers
  reject; it gets a default category axis.
- **Rows taller than a page** are still cut off at the page bottom, as rows
  cannot break across pages, but a warning is now logged through
  `MigraDocLogHost.PdfRenderingLogger`.

### PDF/A and metadata

- **CIDSet for PDF/A-1.** Text outside WinAnsi is embedded as a CID TrueType
  font, and veraPDF refused such PDF/A-1 files (rule 6.3.5-3) because the font
  lacked the CIDSet PDF/A-1 requires. The font descriptor now gets one, also when
  a CID font shares it with a WinAnsi font and when text is added to an opened
  PDF/A-1 file.
- **Generated XMP.** Text is XML-escaped, so a title such as "Profit & Loss" no
  longer makes the metadata unreadable, and characters XML cannot hold are left
  out; line breaks survive parsing; a date the document information lacks is
  left out instead of written as an empty, invalid date; information entries
  that are not text (a number, a dangling reference) no longer make the save
  throw; text strings in PDFDocEncoding are decoded the way readers decode them.
- **`SetPdfA` on an opened file.** A file with XMP of its own kept that XMP
  unchanged, so it did not claim PDF/A at all. The packet is now updated in
  place: it gets the PDF/A identification and the values of the document
  information, and keeps everything else it holds. Annotations that are not
  hidden get the Print flag PDF/A requires, and PDF/A-1 pages lose their
  transparency group.
- **Saving opened PDF/A files.** A `Modify` save changes the modification date,
  the producer and any edited title in the document information, but kept the
  old XMP, and it added a page transparency group, which PDF/A-1 forbids; such
  saves broke conformance. When a file's XMP claims PDF/A, the XMP is now brought
  in line, annotations get the Print flag and no page transparency group is
  added. Incremental updates leave metadata and pages alone.

## Upgrading from 7.7.0

Update all FreePDF packages to 7.8.0 together and rebuild; the assembly version
is now 7.8.0.0. The public API is unchanged except for one addition,
`PdfFontDescriptor.Keys.CIDSet`. Behaviour changes to check:

- Damaged files that threw `PdfReaderException` may now open through the
  rebuild. Code that relied on the exception to reject such files should check
  the result; `Append` mode still throws for them.
- A stream whose length had to be recovered no longer includes the line break
  before `endstream`.
- `CName` values in content streams whose names hold bytes above 127 are decoded
  text instead of raw bytes.
- MigraDoc: justified lines with tabs or fields can be spaced differently; charts
  without X axis settings show a category axis; column, line and area charts
  without Y axis settings render without a value axis instead of throwing.
- Opened files whose XMP claims PDF/A: a `Modify` save rewrites the XMP packet
  (properties that mirror the document information, a standard packet header),
  sets the Print flag on annotations that are not hidden, adds no page
  transparency group and, for PDF/A-1, removes existing ones. `SetPdfA` on an
  opened file does the same and adds the PDF/A identification.
- Generated XMP leaves out empty dates. `DocumentMetadataInfo` returns an empty
  string for information entries that are not text, and decodes strings without
  a byte order mark as PDFDocEncoding.

## Validation

All 7.7.0 release gates apply, plus:

- 115 new regression tests, 838 in all, each failing without its change where it
  guards a fix. They cover padded and mis-sized streams, 38 damaged-file
  recovery cases (object headers in strings and comments, linearized and
  appended trailers, encrypted files, embedded PDFs, linear time on hostile
  input), the MigraDoc crashes and the endless loop, CIDSets, generated XMP and
  the update of existing XMP packets.
- The sample files attached to the upstream issues (31 files) open as before or
  better: the Bluebeam files of issues #186 and #216 open, and the file of #213
  keeps its form.
- A differential fuzz of 4,000 damaged files: the final reader opens 8 more than
  the build of the previous review round and none fewer.
- veraPDF 1b passes PDF/A-1b files with CID subset and complete font embedding,
  mixed WinAnsi and CID text, a FreePDF PDF/A-1b file re-saved in `Modify` mode
  with a new title, a plain file with its own XMP and a link made PDF/A-1b after
  opening, text added to an opened PDF/A-1b file, and XMP values with
  PDFDocEncoding, line breaks and a cleared title; veraPDF 2b passes PDF/A-2b
  output, 3b passes Factur-X invoices new and re-saved, and ua1 and 2a pass PDF/UA
  output.
- MigraDoc: 2,882 scenarios rendered before and after with a proportional font
  and compared by content and line positions; of 1,332 justified scenarios with
  tabs, fields and soft hyphens, 7.7.0 hung on 172 and 7.8.0 on none.
- Independent reviews (five rounds for the reader, two for PDF/A and metadata,
  one for MigraDoc) found issues, including regressions in earlier rounds'
  fixes, which were fixed before release.

### Known limits

- Rebuilding: a text at the start of a line inside a multi-line string that looks
  like an object header is taken for one; a stream without any `endstream`
  swallows the objects behind it; an update appended directly after `%%EOF`
  without a line break is not seen.
- A title or author with a character XML cannot hold, such as U+0002, cannot
  agree with the XMP, so such a PDF/A file fails rule 6.7.3.
- Converting arbitrary content to PDF/A remains out of scope.
