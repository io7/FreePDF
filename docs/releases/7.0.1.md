# FreePDF 7.0.1

FreePDF 7.0.1 changes how the assemblies identify themselves. Library behaviour
and the public API are unchanged from 7.0.0.

## Assembly identity

- The assemblies are strong-named with io7's key, public key token
  `77af05c50284aa70`. 7.0.0 used empira's key, token `f94615aa0424f9eb`.
- The assembly company is io7 and the product is FreePDF.
- The copyright line keeps empira Software GmbH, the original authors, next to
  io7. The MIT licence and third-party notices are unchanged.
- NuGet lists io7 as the package author.

7.0.0 assemblies had the same identity as empira's PDFsharp builds: the same
signing key, company and product name. Loaders and licence scanners could
mistake FreePDF for empira's PDFsharp 7, which is AGPL or commercially
licensed. FreePDF is an independent MIT project and not an empira release.

## Upgrading from 7.0.0

Update `io7.FreePDF` and `io7.FreePDF.MigraDoc` to 7.0.1 together and rebuild.
Code compiled against 7.0.0 references empira's key; do not mix 7.0.0 and 7.0.1
assemblies in one application. The 7.0.0 GitHub release assets remain available
for reference; 7.0.1 is the first version intended for NuGet.org.

## Validation and limits

The 7.0.0 release gates apply unchanged, plus regression tests that check every
shipped assembly's public key token, company, product and empira attribution.
The 7.0.0 migration notes, support policy and feature limits apply unchanged;
see `../migrating-to-7.md` and `../support-policy.md`.
